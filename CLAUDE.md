## АРХИТЕКТУРА v3: SUPABASE FREE + CLOUDFLARE R2 (решение заказчика, 12.10.2026)

Заменяет собственный сервер на Rust (`server/`) и его админку — они остаются в репозитории только до переноса,
дальше не развиваются. Цель — $0 в месяц на объёме школы.

- **Supabase (Free):** Postgres (каталог, уроки, PDF, активации, профили), Auth (ученики: код на email + Google),
  Edge Functions: проверка ключа активации (формула — порт `packages/activation_key`, проверка по `vectors.json`),
  выдача временных ссылок на видео/PDF, ссылки на загрузку для админки. Формулы в приложении больше не будет.
  RLS: каталог — читать опубликованное всем; активации — только свои; запись — только админ.
  Ограничения Free: 500 МБ база, проект «засыпает» после 7 дней без активности.
- **Cloudflare R2 (Free 10 ГБ, трафик бесплатный):** видео, PDF, обложки. Доступ — presigned URL из Edge Function
  (S3-совместимый API; ключи R2 — только в секретах Supabase, не в приложении и не в git).
- **Админка:** веб-страница на Cloudflare Pages (те же разделы: обзор, продукты, редактор с загрузкой и прогрессом,
  ключи + журнал + Excel), работает с Supabase; вход администратора — Supabase Auth + роль admin.
- **Доступ к курсу:** ключ к телефону, как раньше (ID-код из Android ID → ключ), но проверяет Edge Function и
  записывает активацию в аккаунт ученика (user_id + device_code + product). Видео — только по этой записи.
- **Сделано (12.10.2026):** `supabase/` — миграция (таблицы, RLS, триггеры номеров, `reorder_lessons`, статистика
  `sales_totals`/`sales_by_month`/`top_products`, бакет `covers`), функции `activate`, `media-url`, `admin`
  (R2 presign через aws4fetch), формула `_shared/activation.ts`. Проверки: `supabase/tests` (PGlite + node),
  `deno check`. Инструкция по подключению — `supabase/README.md`. Проект: aqihlmikvzdfiutmuwdd (Frankfurt).
  **Веб-админка — `admin-web/`** (статика без сборки, supabase-js с jsDelivr, роутинг по #): вход (почта+пароль,
  проверка `admins`), обзор (rpc статистики), продукты, редактор (обложка → Storage `covers`; видео/PDF → R2 по
  подписанной ссылке из функции `admin`, PUT из браузера с прогрессом; порядок — rpc `reorder_lessons`),
  ключи (функция `admin` generate-key → `sales`; журнал, Excel, отзыв активаций). `_headers` — CSP для Pages.
  Деплой: Cloudflare Pages → Upload assets (см. admin-web/README.md). Publishable-ключ — в `admin-web/config.js`.
  **Приложение на Supabase (12.10.2026):** `core/config/backend.dart` (URL + publishable), `Supabase.initialize` в main;
  каталог `SupabaseCatalogRepository` (`albumFromRow` + тест), вход `SupabaseAuthRepository` (OTP 6 цифр, Google скрыт),
  активация `SupabaseActivationRepository` (функция activate; перед активацией — вход), видео/PDF `SupabaseMediaRepository` (функция media-url). Плеер — video_player (ExoPlayer)
  вместо media_kit (меньше размер), `Playback`: VideoPlayback / TimerPlayback (тесты); полный экран (горизонтально),
  двойное касание ±10 с. PDF — pdfrx + водяной знак с email. FLAG_SECURE на плеере и PDF (`SecureScreen` +
  MethodChannel setSecure); `--dart-define=ALLOW_SCREENSHOTS=true` — только для проверки на эмуляторе.
  Прогресс — локально + upsert в `lesson_progress`. Приложение заблокировано в портретной ориентации.
  Тесты подменяют репозитории моками (helpers.dart). Release arm64 APK ~25.6 МБ (загрузка ~13 МБ; PDFium 6.4 МБ —
  если нужно меньше, заменить pdfrx на системный PdfRenderer).
  Проверено на эмуляторе с реальной базой: каталог, обложка, бесплатное видео из R2.
  Не проверено вживую: вход по коду (нужен шаблон письма с {{ .Token }} и SMTP), активация на сервере, PDF.
  Вход админа — email + пароль (Supabase Auth) + запись в `admins`; ученики — OTP по email (нужен свой SMTP).
- **Активация навсегда на телефоне (требование заказчика 13.10.2026):** принятый ключ сохраняется в настройках
  (`ActivationStore`, ключ `device_activations`: ID-код → {продукт → ключ}). `ownedProvider` берёт открытые курсы
  оттуда — сразу, без сети и без входа; выход из аккаунта и ошибки сети их не убирают. При входе активации этого
  телефона из аккаунта дописываются (восстановление после переустановки, если ID-код тот же). Видео/PDF: приложение
  шлёт в `media-url` ID-код + сохранённый ключ (`mediaPass`), функция пускает по аккаунту ИЛИ по записи в
  `activations` с этим device_code + ключом — вход не нужен. Отзыв в админке (удаление записи) закрывает выдачу
  файлов, но на телефоне курс выглядит открытым (видео — «недоступно»). Случайная цифра ID-кода хранится в
  настройках только у установок до 13.10.2026; новые берут цифру из Android ID (`saltFor`), и после
  переустановки ID-код прежний — старый ключ подходит.
- **Видео без интернета (решение заказчика 13.10.2026):** урок открытого курса, досмотренный до конца, скачивается
  в фоне по любой сети (`features/offline/offline_videos.dart`, очередь `offline_queue`, индекс `offline_index`:
  урок → videoKey; видео заменили — копия обновится). Android 8+: `OfflineVideos.kt` пишет в noBackupFilesDir/offline
  файл «GSV1 + IV + AES-256-CTR», ключ данных обёрнут ключом Android Keystore (не переносится на другой телефон);
  загрузка продолжается с места обрыва. Плеер играет копию через `content://<appId>.offline/v/<урок>`
  (`OfflineVideoProvider`, не экспортирован, StorageManager.openProxyFileDescriptor — расшифровка кусками в памяти,
  перемотка работает). Копия есть — играет она (без сети и трафика); не открылась — удаляется и скачивается снова.
  Профиль: «Видео на телефоне · размер» → удалить все (сами снова не скачиваются, только после нового досмотра).
  Проверено на эмуляторе: скачивание 10,8 МБ, файл без признаков MP4, воспроизведение и перемотка из копии.
- Ждём от заказчика: anon/publishable key, выполнение шагов supabase/README.md (db push, deploy, R2, секреты, админ),
  аккаунт Cloudflare с включённым R2 и бакетом. service_role, пароль БД и ключи R2 в чат НЕ присылать —
  они задаются в секретах Supabase самим заказчиком.

## ОПЛАТА: КЛЮЧ АКТИВАЦИИ, ПРИВЯЗАННЫЙ К УСТРОЙСТВУ (решение заказчика, 12.10.2026)

Эта схема заменяет всё, что ниже в промте сказано про Google Play Billing, `in_app_purchase`,
`/purchases/google/verify`, `/webhooks/google-play`, комиссию Google и «Восстановить покупки».
(Промежуточный вариант с одноразовыми кодами XXXX-XXXX-XXXX заказчик отменил.)

1. Ученик открывает «Активировать курс» и копирует **ID-код устройства**.
2. Платит музыканту вне приложения и отправляет ему ID-код.
3. Музыкант вручную (по своему алгоритму) делает **код активации** и отправляет ученику.
4. Ученик вводит код → приложение проверяет его → курс открыт. Вход в аккаунт для этого не нужен.

- ID-код устройства (`features/purchases/activation_key.dart`, `deviceCode`): Android ID
  (серийный номер и IMEI с Android 10 приложениям недоступны) → латинские буквы в номера
  (A=1…Z=26), цифры как есть → в начало цифра 1–9: с 13.10.2026 — из Android ID (`saltFor`, FNV-1a % 9 + 1, решение заказчика:
  ID-код не меняется после переустановки); у ранних установок — случайная, сохранённая в `device_code_salt` → строка разворачивается. Пример ТЗ: `R5CR319NT7N` + 6 → `41702419138135816`.
  Android ID получаем через MethodChannel `guitar_school/device` в `MainActivity.kt`. iOS — позже.
- Кодирование числа в ключ (`encodeKeyNumber`): после каждой цифры её буква (1→A…9→I), 0 → `0FFF`;
  20986 → `2B0FFF9I8H6F` (пример ТЗ).
- **Алгоритм ключа — вариант A** (выбран заказчиком 12.10.2026, `expectedKey`): каждая цифра ID-кода ×
  номер её места слева направо (с 1), всё сложить → × (номер курса + 3) → + 1985 (секретное число,
  `keySecret`) → `encodeKeyNumber`. Пример: `14140235536843855`, курс 1 → 717 × 4 + 1985 = 4853 → `4D8H5E3C`.
  Считается вручную; ограничения: для одного курса всего ~1400 разных ключей, совпадения у разных
  телефонов возможны, формула лежит в приложении. Предлагались сильнее: B (части кода + остаток),
  C (HMAC с секретом + генератор + проверка на сервере) — заказчик выбрал A. Смена `keySecret` или
  сдвига делает все выданные ключи недействительными.
- Каждый продукт имеет `activationNumber` (номер в алгоритме): ключ открывает только свой продукт.
  **Каждый раздел — только своим ключом (решение заказчика 13.10.2026):** ключ альбома НЕ открывает песни этого
  альбома, проданные отдельно (правило брифа «купил альбом — открыты его песни» и `album_links` отменены).
  `Ownership.owns` = только свой id; `media-url` проверяет активацию именно этого продукта; поле «Входит в альбом»
  убрано из админки. Таблица `product_links` в базе осталась, но ни на что не влияет.
  Тестовый каталог: 1 «Гитара с нуля», 2 «Далер Назаров», 3 «Муборакшох», 4–6 отдельные песни.
- Проверка сейчас в приложении (`LocalActivationRepository`): ключи хранятся в настройках
  (`activations`) и перепроверяются при каждом запуске по коду устройства — копия настроек на
  другом телефоне курсы не откроет. Рекомендовано перенести проверку на сервер (алгоритм не будет
  лежать в приложении, сервер узнает, кому выдавать видео, админка увидит активации) — ждём решения.
- Формула живёт в общем пакете `packages/activation_key` (чистый Dart, свои тесты); его используют
  приложение и генератор. Менять формулу — только там.
- **Генератор ключей — приложение `keygen/`** (Flutter, Android, для телефона музыканта; НЕ публиковать):
  ID-код ученика (кнопка «Вставить») → курс → ключ + расчёт → «Отправить» (share sheet) / «Скопировать».
  Курсы и номера — `keygen/lib/courses.dart`, должны совпадать с `activationNumber` каталога. Консольный
  вариант: `cd app && dart run tool/activation_key.dart <ID-код> <номер курса>`. В админке (этап 6) — такой же генератор.
- ПРАВИЛО GOOGLE PLAY: внутри приложения нельзя направлять на оплату в обход Google — никаких цен,
  «купить», реквизитов, телефонов/WhatsApp рядом с закрытым курсом. Контакты школы — только в Профиле,
  без слов об оплате. Как получить ключ — рассказывается вне приложения (школа, соцсети).
  Подсказка с телефоном/WhatsApp — только в сборке для прямой раздачи APK:
  `--dart-define=DISTRIBUTION=direct` (`core/config/distribution.dart`, в тестах — `distributionProvider`).
  В ней кнопка на закрытом курсе — «Купить», в окне активации — «Как купить: отправьте ID-код…»,
  кнопки WhatsApp (wa.me с готовым сообщением: курс + ID-код) и «Позвонить».
  Номер — `School.contactNumber` (сейчас заглушка 992000000000, ждём настоящий).
  Google Play подписывает приложение своим ключом (Play App Signing), поэтому ID-код в версии из
  Google Play и в APK прямой раздачи на одном телефоне будет разным — ключи выдаются под ту версию,
  что установлена.
- Приложение бесплатное → платёжный профиль продавца в Google Play не нужен, только аккаунт разработчика.

## Принятые решения (сверх промта)

- Токены дизайна: единый источник `design/tokens.json`. После правки запусти
  `dart run tools/gen_tokens.dart` — он перегенерирует `app/lib/core/theme/tokens.g.dart`
  и `admin/static/tokens.css` и проверяет контраст WCAG AA. Сгенерированные файлы руками не править; CI проверяет, что они актуальны.
- Шрифт Manrope не содержит таджикских букв (Ғ ғ Ӣ ӣ Қ қ Ӯ ӯ Ҳ ҳ Ҷ ҷ). Для них подключён
  `InterTajik` — подмножество Inter только из этих 12 пар букв (fontFamilyFallback). Шрифты лежат в `app/assets/fonts`, лицензии OFL рядом.
- В светлой теме `accent-on` = #1A1206 вместо #FFFFFF из брифа: белый на #C9822A даёт контраст 3.1:1 (< AA 4.5:1).
- Добавлены токены, которых нет в брифе: `border` и `danger` (цвета взяты из макетов админки).
- Flutter не поставляет Material-локализацию для таджикского (`tg`) — для неё берётся русская (см. `core/l10n/fallback_localizations.dart`).
- **База — SQLite** (решение 12.10.2026, вместо PostgreSQL из брифа): один файл `DATA_DIR/school.db`, WAL; локально
  ничего ставить не нужно, на сервере — один контейнер. Миграции `server/migrations` встраиваются в бинарник.
- **Файлы — на диске сервера** (`DATA_DIR/media/{videos,pdfs,covers}/<uuid>.<ext>`), без Bunny на старте. Видео и PDF
  отдаются только по ссылке с HMAC-подписью на 2 часа (`MEDIA_SECRET`), с Range (перемотка). Обложки — открыто.
  Абстракция под Bunny Stream — при росте нагрузки (`media.rs` — единственное место).
- **Админка** (`server/src/admin/`): страницы рисует сервер (maud), `admin/static/admin.js` — прогресс загрузки видео
  (длительность читает браузер), перетаскивание уроков (и стрелками), копирование. Вход: логин/пароль (argon2),
  сессия в cookie `gs_admin` (HttpOnly, SameSite=Strict, в базе — SHA-256 токена), проверка Origin на POST.
  Администратор: `guitar_school_server admin <логин> <пароль>` или ADMIN_USERNAME/ADMIN_PASSWORD при первом запуске.
- Публикация запрещена, пока нет уроков или у какого-то урока нет видео. Продукт с выданными ключами удалить нельзя.
- `activation_number` продукта выдаётся автоматически (max+1) и не меняется — на нём держатся выданные ключи.
- Формула ключа на сервере — `server/src/activation.rs`; совпадение с Dart проверяет общий файл
  `packages/activation_key/test/vectors.json`.
- Журнал ключей (`activations`) — это продажи для статистики; ключи из генератора на телефоне туда не попадают,
  их можно внести той же формой. Отзыва ключей пока нет (приложение проверяет ключ само).
- Ограничение: превью отдельной песни (первые N секунд) ограничивает приложение, а сервер отдаёт файл целиком.
- Экраны сделаны до сервера. Данные идут через интерфейсы `CatalogRepository`, `AuthRepository`,
  `PurchaseRepository` с временными реализациями `Mock*` (тестовый каталог в `features/catalog/data/mock_catalog.dart`;
  вход принимает любой 4-значный код). Прогресс уроков — в SharedPreferences.
  На этапах 2/4/5 заменить реализации на API; экраны и провайдеры не меняются.
- Плеер имитирует видео таймером (`features/player/playback.dart`) до этапа 4; страницы нот — нарисованная заглушка.
- Иконки — Lucide через свой класс `AppIcons` и шрифт `assets/fonts/Lucide.ttf` (release оставляет ~8 КБ).
  Пакет lucide_icons_flutter убран: он добавлял ~1,4 МБ неиспользуемых шрифтов. Залитые play/pause — Material Rounded.
- Размер: release arm64 APK ~17 МБ, загрузка из Google Play ~8 МБ (движок Flutter — 11,75 МБ из них). Релиз собирать
  с `--obfuscate --split-debug-info` (команды в README).
- Нижние листы из вкладок открываются с `useRootNavigator: true`, иначе их перекрывает нижняя панель.
- Автоповтор Riverpod 3 отключён (`retry: noRetry`, `core/config/retry.dart`): по умолчанию он до 10 раз
  молча повторял упавший запрос и показывал загрузку минутами. У всех сетевых вызовов есть таймаут
  (каталог 15 с, функции 20 с, видео 30 с). Каталог кэшируется в настройках (`catalog_cache_v1`):
  показывается сразу, свежий грузится в фоне.
- Разрешение INTERNET прописано в `android/app/src/main/AndroidManifest.xml`: шаблон Flutter даёт его только
  debug/profile, и release без него не видел сеть (на телефоне — «Не удалось загрузить»). Тест `android_manifest_test.dart`.
  Сетевые функции проверять на release-сборке, не только через `flutter run`.
- applicationId `com.guitarschool.guitar_school` — временный; заменить на домен школы ДО первой публикации в Google Play.

## Продукт
- Музыкант продаёт 3 типа продуктов. Каждый покупается отдельно, разовой покупкой, доступ навсегда:
  1. «Курс для новичков» (type = course): 10 видеоуроков + PDF-материалы. Цена 150 сомони.
  2. «Альбом песен» (type = song_album): 10 песен (например, песни Далера Назарова, Муборакшох), к каждой песне свой видеоразбор и свой PDF с нотами. Цена 200 сомони за альбом.
  3. «Отдельная песня» (type = single): одна песня, видеоразбор + PDF с нотами. Цена [цена] сомони.
- У всех продуктов общая структура: обложка + список уроков (видео) + материалы (PDF).
- Одна и та же песня может продаваться и отдельно, и в составе альбома. Если пользователь купил альбом, отдельные песни из него у него уже открыты.
- Все продукты платные. Бесплатное превью: первый урок курса, первая песня альбома, первые 30–60 секунд отдельной песни.
- Пользователь: смотрит каталог → открывает альбом → смотрит превью → покупает → получает доступ ко всем видео и PDF навсегда.
- Главное требование заказчика: МИНИМАЛИЗМ. Минимум текста, крупные обложки, иконки вместо слов, 1–2 действия на экране.
- Языки интерфейса: русский, таджикский, английский (через ARB-локализацию).

## Архитектура
### Мобильное приложение (папка /app)
- Flutter 3 (последняя стабильная), Dart 3, null safety.
- Состояние: Riverpod. Навигация: go_router.
- Сеть: dio + сгенерированные модели (freezed + json_serializable).
- Видео: media_kit (HLS-стриминг, скорость 0.5x–1.25x, повтор фрагмента A–B, полноэкранный режим, жесты перемотки).
- PDF: pdfrx (просмотр внутри приложения, масштаб, ночной режим).
- Покупки: официальный плагин in_app_purchase (Google Play Billing; позже App Store). Покупка НЕ считается завершённой, пока сервер не подтвердил её.
- Защита от записи экрана на Android: FLAG_SECURE на экранах видео и PDF.
- Хранение токена: flutter_secure_storage.
- Тема: тёмная по умолчанию + светлая. Все цвета, шрифты и отступы — из единого файла design tokens (см. дизайн-контекст).
- Структура: feature-first (features/catalog, features/album, features/player, features/pdf, features/purchases, features/auth, features/profile), core/ (theme, network, router, l10n).

### Сервер (папка /server)
- Rust (stable), Axum, Tokio, SQLx + PostgreSQL, миграции SQLx.
- Авторизация: вход по email-коду (OTP) и через Google Sign-In; выдача JWT (access + refresh).
- Видео: хранятся в сервисе видеостриминга с HLS (например, Bunny Stream или Cloudflare Stream — сделай слой абстракции `VideoProvider`, чтобы провайдера можно было сменить). Сервер выдаёт только короткоживущие подписанные ссылки и только купившим.
- PDF: в S3-совместимом хранилище; выдача через подписанную ссылку; при выдаче на PDF ставится водяной знак с email покупателя.
- Проверка покупок: Google Play Developer API (purchases.products.get), затем acknowledge. Обработка Real-time Developer Notifications (возвраты → отзыв доступа).
- Конфигурация через переменные окружения, секреты не коммитить. Логи: tracing. Ошибки: thiserror + единый формат JSON-ошибок.
- Docker + docker-compose для локального запуска (server + postgres).

### Админ-панель (папка /admin)
- Простая веб-панель для музыканта (можно отдавать с того же Rust-сервера, минимальный HTML + HTMX или небольшое SPA).
- Вход только для администратора (роль admin), отдельный от учеников.
- Обзор: число пользователей (+ новые за период), продажи, выручка, комиссия Google Play (процент настраивается), чистая прибыль; график выручки по месяцам; лучшие продукты; последние покупки. Переключатель периода: неделя / месяц / год.
- Продукты: таблица всех курсов, альбомов и песен (тип, число уроков, цена, продажи, статус «Опубликован/Черновик»), фильтр по типу.
- Редактор продукта: тип (курс / альбом песен / отдельная песня), название, описание в 1–2 строки, цена в сомони, уровень, ID товара в Google Play, обложка; список уроков или песен с перетаскиванием порядка, загрузкой видео (с прогрессом) и PDF к каждому; отметка «бесплатное превью»; превью карточки как в приложении; кнопки «Сохранить черновик» и «Опубликовать».
- История покупок: дата, покупатель (email частично скрыт), продукт, сумма, комиссия, чистыми, статус (оплачено / возврат); поиск по email, фильтры по периоду и продукту, выгрузка в Excel.
- Пользователи: список с датой регистрации и покупками.

## Модель данных
- users: id, email, name, locale, created_at
- albums: id, type (course | song_album | single), title, subtitle, cover_url, level (beginner | intermediate | advanced), play_product_id, price_display, is_published, sort_order
- lessons: id, album_id, title, order, duration_sec, video_asset_id, is_free_preview
- materials: id, album_id, lesson_id (nullable: PDF конкретной песни), title, file_key, kind (pdf)
- album_links: song_album_id, single_id (песня из альбома ↔ та же песня как отдельный продукт; покупка альбома открывает связанные отдельные песни)
- purchases: id, user_id, album_id, platform (google_play | app_store), purchase_token, status (pending | active | refunded), created_at
- lesson_progress: user_id, lesson_id, position_sec, completed

## API (REST, JSON, префикс /api/v1)
- POST /auth/otp/request, POST /auth/otp/verify, POST /auth/google, POST /auth/refresh
- GET /albums — каталог (фильтр type, level)
- GET /albums/{id} — альбом + уроки + флаг owned
- GET /lessons/{id}/stream — подписанная HLS-ссылка (403, если не куплено и не превью)
- GET /materials/{id}/download — подписанная ссылка на PDF с водяным знаком
- POST /purchases/google/verify — проверка токена покупки, выдача доступа
- GET /me/library — купленные альбомы
- PUT /me/progress/{lesson_id} — сохранить позицию просмотра
- POST /webhooks/google-play — уведомления Google (возвраты, отмены)

## Контекст дизайна

Настроение: тёплая тёмная «сцена» с акцентом цвета дерева гитары. Минимум текста, максимум обложек и иконок.

### Принципы
- Одно главное действие на экране, оно всегда заметнее всего остального.
- Иконки вместо слов, где смысл понятен без подписи (замок, галочка, PDF, play).
- Крупные обложки альбомов, фото музыканта и гитары как главный визуальный язык.
- Много воздуха: отступы важнее рамок и разделителей.
- Тексты не длиннее одной строки; описания альбомов максимум 2 строки.

### Палитра, шрифты, размеры
Все значения — в `design/tokens.json` (тёмная тема по умолчанию + светлая). Шрифт Manrope.
Заголовок экрана 28/Bold, название альбома 22/Bold, урок 16/SemiBold, подписи 13/Medium.
Сетка 8 pt (8, 16, 24, 32), боковые поля 20. Скругления: карточки 20, кнопки 16, обложки в списке 12.
Зона касания ≥ 48 dp. Иконки Lucide (или Material Symbols Rounded), линия 2, размер 24.

### Компоненты
- Карточка альбома: обложка 1:1, скругление 20, снизу название (1 строка) и маленькая метка уровня. Купленный — тонкая полоска прогресса акцентом под обложкой.
- Строка урока: номер в круге, название, длительность; иконка состояния play / замок / галочка. В альбоме песен ещё иконка PDF с нотами песни.
- Главная кнопка: на всю ширину, высота 56, акцент, «Купить · [цена]» или «Смотреть».
- Плашка PDF: иконка документа + «Ноты», открывается одним касанием.
- Нижняя панель: 3 иконки — Главная, Библиотека, Профиль.
- Плеер: тёмный фон, крупная play, ползунок акцентом, скорость (0.5×, 0.75×, 1×), повтор A–B.

### Экраны
- Онбординг: фото музыканта с гитарой на весь экран, затемнение снизу, одна фраза, «Начать».
- Вход: логотип школы, email, «Получить код», кнопка Google.
- Главная: приветствие одним словом, карточка «Продолжить», ряды «Курс для новичков», «Альбомы песен», «Отдельные песни».
- Альбом: обложка на верхнюю треть с размытым фоном, название, уровень, число уроков, главная кнопка, плашка PDF, список уроков.
- Плеер: видео сверху, название урока, скорость, A–B, «Следующий урок».
- PDF: ноты на весь экран, сверху только «назад» и масштаб.
- Библиотека: сетка купленных альбомов с прогрессом; пустое состояние — иллюстрация гитары + «В каталог».
- Профиль: аватар, язык, тема, «Восстановить покупки», контакты школы.

### Избегать
Длинных описаний, баннеров, рекламных всплывающих окон; ярких градиентов, неона, более одного акцента;
стоковых фото (только реальные фото музыканта, школы, гитар); мелкого серого текста на тёмном фоне.
